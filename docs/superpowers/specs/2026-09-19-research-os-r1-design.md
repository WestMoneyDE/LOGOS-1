# LOGOS-1 Research Operating System — R1 design (spec)

**Order:** `LOGOS1-RESEARCH-OPERATING-SYSTEM-DASHBOARD-R1` (founder master order, 107 sections, delivered 2026-09-19) · **ADR:** `docs/adr/ADR-LOGOS1-RESEARCH-OPERATING-SYSTEM-R1.md` · **Inventory:** `RESEARCH-OS-CURRENT-STATE.md` · **Target:** `RESEARCH-OS-TARGET-ARCHITECTURE.md`
**Founder decisions (brainstorm 2026-09-19):** hybrid execution (Claude host executor, rest Docker) · run console with Start/Pause/Stop (no free chat) · agent autonomy up to `PREREG_DRAFT` + work-order DRAFT, founder gates after · PostgreSQL queue in the lab DB · German UI default, EN switch.

## 1. Goal
Turn the read-only scientific dashboard into an operable Research OS: plan → preregister → execute → observe → evaluate → compare → document → next order, with the existing registries as scientific truth and every autonomous step gated.

## 3. Data model (Postgres `ros_*`, migrations in `src/logos_dashboard/db/migrations/`)
`ros_theses` (thesis_id, claim_ids[], title, track, state, owner, created_at) · `ros_thesis_events` (event_id, thesis_id, from_state, to_state, actor, reason, source_record, git_commit, at) · `ros_work_orders` (work_order_id, thesis_id, state DRAFT|APPROVED|READY|RUNNING|BLOCKED|FAILED|VALIDATED|FALSIFIED|SUPERSEDED, spec jsonb with the §12 mandatory fields, prereg_hash, approved_by, approved_at) · `ros_work_order_deps` (child, parent, mandatory) · `ros_runs` (run_id, work_order_id, thesis_id, kind deterministic|claude, state, branch, worktree, artifact_dir, mlflow_parent_run, trace_root, started, finished, stop_reason) · `ros_run_events` (seq, run_id, at, kind, payload jsonb, privacy_class) · `ros_jobs` (job_id, idempotency_key, kind, run_id, work_order_id, state queued|waiting_quota|waiting_dependency|waiting_governance|running|paused|failed|done|stopped, attempt, locked_by, locked_at, payload, result) · `ros_decisions` (decision_id, kind, subject_ref, state WAITING|APPROVED|REJECTED|DEFERRED|SUPERSEDED, why, impact, if_approved, if_rejected, blocks[], decided_by, decided_at) · `ros_inbox_items` / `ros_radar_items` (pipeline states §15) · `ros_notes` · `ros_benchmark_suites`, `ros_benchmark_snapshots`, `ros_metric_results`, `ros_monthly_snapshots` · `ros_artifacts` (artifact_id, sha256, uri, kind, run_id) · `ros_trace_links` (run_id, mlflow_run_id, trace_id) · `ros_audit` (append-only). Git registries remain the scientific record; the DB never holds a claim status the registry does not.

## 4. State machines
Thesis (§6) and work order (§13) as pure functions `transition(state, event, actor) -> state | error` in `logos_dashboard/control/state_machines.py`; every transition writes an event; illegal transitions raise; drag-and-drop on the board calls the same function. Gates that only the founder may pass: `PREREG_FROZEN`, `WORK_ORDER_READY` (APPROVE), `READY_TO_RUN`, concurrency-cap increase, benchmark definition change, claim-status change.

## 5. Queue, worker, executor
Queue = `ros_jobs` with `SELECT … FOR UPDATE SKIP LOCKED`; idempotency key = `(work_order_id, run_id, kind, attempt_group)`; restart never duplicates Claude invocations, commits, artifact writes or verdicts. `ConcurrencyGovernor` (max_active_theses, max_parallel_deterministic_jobs, max_parallel_claude_sessions = governed cap from `INFERENCE-GOVERNANCE.json`, max_total_claude_invocations, quota/provider/governance state) gates dequeue. Deterministic worker (Docker) handles `prior_art`, `tests`, `dataset`, `dry_run`, `rescore`, `playwright_qa`, `snapshot`. Claude host executor handles `claude` jobs only when the work order is APPROVED + prereg frozen + gates PASS + token minted; uses `ClaudeCodeMaxProvider` + `result_model`, isolated worktree (`git worktree add`), contamination check, stream of structured events; STOP is graceful (§73).
Agent job for a selected thesis (`thesis_advance`): a Claude host job whose prompt is the thesis packet (claim, scope, existing evidence, registries excerpt) and whose allowed outputs are files under `docs/research/dashboard/theses/<id>/` (prior-art brief, question, hypotheses, metrics mapping, falsification criterion, prereg draft, work-order DRAFT) plus deterministic tests — never registry edits, never inference runs. The agent decides whether to request a `prior_art` deep-research sub-job (heuristic in the packet: < 3 citations for the track or none for the claim).

## 6. Run console (`/runs/[run_id]/live`)
SSE from `ros_run_events`: phase, current Claude invocation (model requested/resolved, evidence class, tokens if exposed), current span, stdout events (privacy class), tests, metrics, artifacts (hash), quota, retries, hard-stop status, elapsed. Controls: Start (enqueue approved job), Pause, Stop (graceful), open trace / worktree / prereg / artifacts. Message box → `ros_notes` (decision flag) → injected as "founder notes" into the next job packet. No shell.

## 7. MLflow / OTel
MLflow backend → lab Postgres, artifacts → MinIO. Experiment = track; parent run = work-order execution; child run = arm/replicate; trace = one agent execution; spans `logos.work_order → logos.prereg | logos.dataset.validate | logos.prompt.render | gen_ai.claude.invoke | logos.parse | logos.metric.compute | logos.scorer.run | logos.artifact.write | logos.test.run | logos.git.commit | logos.verdict`. Tags `logos.thesis_id … logos.artifact_hash`; GenAI attributes `gen_ai.operation.name/provider.name/request.model/response.model`, token usage when exposed; privacy classes `METADATA_ONLY | SYNTHETIC_FULL | REDACTED | HASH_ONLY` (synthetic runs may use SYNTHETIC_FULL). Trace explorer `/traces`: span tree/waterfall, filters, deep link to MLflow; re-score existing traces with code scorers only (`NO NEW MODEL INFERENCE`).

## 8. Benchmarks, statistics, snapshots
Suites: `AUTHORITY_GOLDEN`, `PROVENANCE_GOLDEN`, `TRAJECTORY_GOLDEN`, `MEMORY_GOLDEN`, `COGNITIVE_PROVENANCE_GOLDEN`, `REGRESSION_GOLDEN` (from deterministic fixtures + curated traces). Modes `BASELINE_AGENT | LOGOS_AGENT | LOGOS_ABLATION | PREVIOUS_MONTH | PREVIOUS_RELEASE`; dimensions per §29; hard gates per §30; formulas per §31 (pp delta, relative, error reduction, efficiency; `NOT_DEFINED` on zero denominators); comparability badge per §80; monthly immutable snapshots per §33; charts (Recharts via shadcn Chart) always with N, CI, version, comparability. Statistics module: Wilson, Newcombe, bootstrap CI, effect sizes, confusion matrices, calibration, paired comparisons — each result carries method/assumptions/N/missingness/version.

## 9. Inbox, radar, notes, decisions
`/inbox` quick capture (§14) → `/radar` pipeline RAW→…→ACCEPTED/REJECTED/DEFERRED (§15); accepted deltas become drafts (claim/invariant/prior-art/open question/work order) shown as BEFORE / PROPOSED / EVIDENCE / WHY / WHAT WOULD FALSIFY IT and need founder confirmation (§16). Optional radar-processing Claude job produces `AI_PROPOSAL` with input/prompt hashes, model pin, trace id (§40). `/notes` lab notebook with promote actions (§41). `/decisions` gate center (§42). Attention queue (§43).

## 10. Integrity, security, performance
Pre-run integrity gate (§75) enforced in the API before any `claude` job; deviation log (§76); benchmark release gate (§77); hard stops (§100). Browser never sees Claude tokens/env secrets; allowlisted commands only; API bound to localhost/Docker network. Server pagination/virtualisation, debounced search, lazy charts, query caching.

## 11. Testing (§101)
Python: state machines, queue idempotency, DAG, governance gates, executor contract (fake `claude`), auth contamination, MLflow mapping, OTel attributes, benchmark formulas, comparability, snapshot immutability, radar-to-work-order, scientific integrity (existing). Playwright: e2e per core route × 6 viewports, overflow/clipping/console/failed-request gates, visual snapshots (`toHaveScreenshot`), route inventory → `/system/qa`. Screenshots at 1920/1440/1280/1024/390 for the ten §102 screens reviewed before closure.
